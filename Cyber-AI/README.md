# Cyber AI

**وكيل ذكاء اصطناعي قابل للتشغيل داخل Termux**  
قادر على استخدام الأدوات، قراءة مصادر الإنترنت، بناء قاعدة معرفة، امتلاك ذاكرة، والتطور لاحقًا إلى نموذج له أوزانه الخاصة.

---

## الرؤية العامة

Cyber AI ليس شات بوت عادي.

هو **نظام وكيل (Agentic System)** يعمل داخل بيئة Termux، يستطيع:

- فهم طلب المستخدم
- وضع خطة تنفيذية
- استخدام أدوات حقيقية (ملفات، شل، إنترنت...)
- الرجوع إلى قاعدة معرفة متخصصة
- تذكر ما حدث في المحادثات السابقة
- طلب الإذن قبل تنفيذ أي عملية خطرة
- التطور لاحقًا ليصبح نموذجًا مدربًا بأوزان خاصة

الهدف النهائي: تحويل الذكاء الاصطناعي من مجرد "مُجيب" إلى **وكيل فعّال** ينفذ المهام داخل الجهاز.

## تفاصيل المكونات

### 1. `agent/` — عقل الوكيل

هذا أهم جزء في المشروع.

#### `core.py`
القلب الذي ينسق كل شيء:

```text
المستخدم → Agent → Planner → Tools → Permission → تنفيذ → Observation → Agent → إصلاح أو إنهاء
```

يعمل كحلقة (Loop) مستمرة حتى يتحقق الهدف أو يفشل بعد عدد محاولات محدد.

#### `planner.py`
يحول الطلب إلى خطوات منطقية.

مثال:  
طلب: «سوّ لي برنامج Python لإدارة المصاريف»

الخطة المحتملة:
1. فهم المتطلبات
2. اختيار هيكل المشروع
3. إنشاء الملفات
4. كتابة الكود
5. تشغيل اختبارات
6. إصلاح الأخطاء
7. إبلاغ المستخدم

لاحقًا يصبح التخطيط ديناميكيًا:

```text
Goal → Reasoning → Plan → Tool Call → Observation → Next Action
```

#### `executor.py`
يحول قرار النموذج إلى استدعاء أداة حقيقية.

- النموذج يقول: «اقرأ ملف app.py» → يستدعي `read_file()`
- النموذج يقول: «شغّل الاختبارات» → يستدعي `shell()`

#### `permissions.py` — بوابة الصلاحيات

نظام تحكم صارم:

```json
{
  "file_read": "allow",
  "file_write": "ask",
  "shell_execute": "ask",
  "internet_read": "allow",
  "package_install": "ask",
  "git_push": "deny"
}
```

الخيارات الممكنة لكل صلاحية:
- `allow` → تنفيذ مباشر
- `ask` → يسأل المستخدم
- `deny` → يرفض تمامًا

بهذا الشكل أنت تتحكم في الوكيل بدل أن تعطيه صلاحيات مطلقة.

#### `tools/`
أدوات الوكيل:

| الأداة          | الوظيفة                        |
|-----------------|--------------------------------|
| `shell`         | تنفيذ أوامر Termux             |
| `filesystem`    | قراءة / كتابة / حذف ملفات      |
| `web`           | قراءة صفحات من الإنترنت        |
| `python_exec`   | تشغيل كود Python               |
| `git`           | عمليات Git                     |
| `search`        | بحث داخل المعرفة أو الذاكرة    |

### 2. `knowledge/` + `rag/`

**المعرفة** ≠ **الذاكرة**

- **Knowledge**: معلومات عامة (توثيق Python، أوامر Linux، مفاهيم الأمن السيبراني...)
- **Memory**: ما حدث أثناء استخدامك للوكيل (المشاريع السابقة، الأخطاء، القرارات)

نظام RAG يعمل كالتالي:

```text
سؤال المستخدم
      ↓
تحويل السؤال إلى Embedding
      ↓
البحث في Vector Index
      ↓
استرجاع المقاطع الأكثر صلة
      ↓
إعطاؤها للنموذج مع السؤال
      ↓
الإجابة أو التخطيط
```

هذا يجعل الوكيل قادرًا على الرجوع إلى مصادر حديثة ودقيقة دون الاعتماد فقط على الأوزان.

---

### 3. `crawler/`

خط أنابيب جمع المعرفة:

```text
URL → Download → Extract → Clean → Remove Duplicates → Knowledge Base
```

يحترم:
- robots.txt
- شروط الاستخدام
- التراخيص
- حقوق إعادة التوزيع

لا يتم جمع الإنترنت عشوائيًا.

---

### 4. `memory/`

ثلاثة أنواع:

1. **Short-term Memory**  
   سياق المحادثة الحالية.

2. **Long-term Memory**  
   معلومات مهمة محفوظة على المدى الطويل (Vector + ملخصات).

3. **Episode Logger**  
   سجل كامل لما فعله الوكيل في كل مهمة (للتحليل والتحسين لاحقًا).

---

### 5. `model/` + `training/` + `data/`

الهدف طويل الأمد: امتلاك نموذج خاص بأوزان مدربة.

الخط الكامل:

```text
مصادر → raw/ → cleaned/ → datasets/ → Tokenizer → Training → Weights → Model
```

المراحل:
- `data/raw/` : البيانات كما جُمعت
- `data/cleaned/` : بعد إزالة HTML والتكرار والمحتوى التالف
- `data/datasets/` : النسخة النهائية للتدريب

---

### 6. `web/`

واجهة دردشة بسيطة في البداية، ثم تتطور إلى:

- عرض طلبات الإذن (Allow / Deny)
- عرض خطة الوكيل
- عرض نتائج الأدوات
- سجل المهام

---

### 7. `config/` و `prompts/`

- `settings.py` و `permissions.json` → كل الإعدادات في مكان واحد
- `prompts/` → قوالب النظام والتخطيط والتنفيذ (يسهل تعديل سلوك الوكيل دون لمس الكود)

## سيناريو التشغيل الكامل

**الطلب:**  
«سوّ لي برنامج Python لإدارة الملفات»

**ما يحدث داخليًا:**

1. فهم الطلب
2. وضع خطة
3. البحث في Knowledge (إن لزم)
4. تحديد الأدوات المطلوبة
5. كتابة الكود
6. المرور على Permission Gate
7. إنشاء الملفات داخل Termux
8. تشغيل البرنامج
9. قراءة النتيجة
10. اكتشاف الأخطاء (إن وجدت)
11. تعديل الكود
12. إعادة الاختبار
13. تسليم النتيجة النهائية للمستخدم

## مبادئ التصميم

1. **التحكم للمستخدم دائمًا**  
   لا شيء خطير ينفذ بدون إذن.

2. **الفصل الواضح بين المكونات**  
   Agent ≠ Knowledge ≠ Memory ≠ Model

3. **القابلية للتوسع**  
   إضافة أداة جديدة أو مصدر معرفة جديد يكون سهلًا.

4. **الأمان أولًا**  
   خاصة أن الوكيل يعمل داخل Termux ويستطيع تعديل الملفات وتشغيل أوامر.

5. **التطور التدريجي**  
   ابدأ بوكيل يعمل بأدوات، ثم أضف المعرفة، ثم الذاكرة، ثم التدريب.

## الخلاصة

Cyber AI ليس نموذجًا واحدًا.  
هو **منظومة كاملة** تتكون من:

- وكيل يفكر ويخطط
- أدوات حقيقية
- بوابة صلاحيات
- قاعدة معرفة + RAG
- ذاكرة
- مسار نحو نموذج خاص

هذا التصميم أفضل بكثير من محاولة صنع «نموذج يعرف كل شيء» من اليوم الأول.
